# PassBuddy 受控内测范围与决策

> 状态：Approved for documentation
> 目标阶段：受控外部内测（Beta-Lite）
> 目标规模：2 所高校、约 100 名受邀用户

## 1. 业务目标

在不重做现有面试闭环的前提下，让真实高校用户可凭邮箱验证码和邀请码进入系统，完成可追踪的面试训练，并让团队获得可复查的完成率、质量反馈、失败率和成本数据。

## 2. 用户与主闭环

### 用户

- 学生用户：受邀请码控制，使用邮箱验证码登录并完成训练。
- 运营管理员：维护学校和邀请码、查看聚合指标、处理数据删除请求。
- 开发/值班人员：处理错误告警和阻塞性故障，不默认查看用户正文。

### 主闭环

1. 用户输入邮箱，请求并验证数字验证码；首次验证创建账号，后续验证登录既有账号。
2. 尚未取得内测资格的已登录用户额外输入邀请码，成功消费后绑定学校并开通产品体验；已激活用户后续登录不再输入邀请码。
3. 用户阅读并同意当前版本隐私协议。
4. 用户输入简历/JD、选择面试官并完成现有画像、出题、作答和报告闭环。
5. 系统在关键节点持久化训练状态和结果。
6. 报告展示后，用户可提交 1–5 星和一句话反馈。
7. 管理员查看聚合指标并按需要处理邀请码、故障和删除请求。

## 3. 已冻结决策

| ID | 决策 | 结论 |
| --- | --- | --- |
| D-01 | 阶段 | 受控外部内测 Beta-Lite，不按公开 Beta 或正式商用标准扩张 |
| D-02 | 平台与组件 | Next.js 内自托管 Better Auth；线上使用同地域/VPC 的腾讯云 PostgreSQL；验证码通过腾讯云 SES SendEmail API 发送 |
| D-03 | 登录方式 | 仅邮箱登录；内测期 6 位数字 OTP 暂设 30 分钟有效，以减少测试中因超时造成的重复发信；60 秒后可重发；最多 3 次错误尝试；重发生成新码并使旧码失效；安全 Cookie Session；正式上线前收紧至 5–10 分钟并重新执行 Auth 验收；放量前实测 QQ/163/学校域名 |
| D-04 | 准入 | 邮箱 OTP 注册/登录与内测资格分离；邀请码绑定学校，只在账号首次开通产品体验时消费；已有 active profile 后续登录不再要求邀请码；邮箱域名仅作辅助规则 |
| D-05 | 保存范围 | 保存简历/JD 文本、画像、题目、转写文本、报告与关键事件；不保存原始音频 |
| D-06 | 保留删除 | 内测结束后默认保留 90 天；删除请求由管理员人工执行并留痕 |
| D-07 | 反馈 | 报告展示后自愿提交，不阻断报告查看 |
| D-08 | 管理权限 | `user/admin` 两类角色；管理页和管理 API 仅 admin 可访问 |
| D-09 | 指标权威源 | 服务端数据库事件和业务表为完成率/错误率权威源；客户端事件只补充页面漏斗 |
| D-10 | 法务文案 | 产品/法务提供最终文本；开发实现版本化展示、同意记录和更新提醒 |
| D-11 | SES 额度保护 | 30 分钟有效期只用于降低正常超时重发，不作为额度控制；OTP 请求同时执行单邮箱/IP 日限额和全局可配置发送预算；达到预算阈值后停止发送、返回稳定错误并告警；不把当前免费额度硬编码到业务代码 |
| D-12 | 体验次数 | 每个成功使用邀请码激活的账号暂有 3 个完整面试会话名额；邀请码可激活人数上限与单账号会话上限分别配置；创建新会话时占用，恢复同一会话不重复占用 |
| D-12A | 邀请码批量创建 | 管理员一次可批量生成多个结构相同、明文各自唯一的邀请码；`batchCount` 默认 1，单码 `maxUses` 默认 1 但仍可调整，单账号会话上限默认 3；批量创建必须同事务完成，明文仅在成功响应中显示一次 |
| D-13 | 语音依赖冗余 | 保持 `/api/tts`、`/api/stt` 和前端状态枚举兼容；Azure 为当前主 provider，新增一个真实服务端备用 TTS/STT provider。主、备均失败后，TTS 降级到 Web Speech/文本，STT 降级到浏览器识别/手动编辑；备用厂商须在地域、价格、隐私和真实中文样本核对后另行确认 |
| D-14 | 国内前端应用监控 | 使用腾讯云 RUM 广州项目作为 staging 前端异常/性能真实接收面；不接入跨境监控，不购买 CLS。SDK 必须显式启用且默认 fail-off，固定中国大陆接收域名；禁用真实用户标识、持久设备 ID、Cookie、请求/响应正文、URL query、页面截图和全量日志。服务端继续保持 vendor-neutral JSON/requestId，RUM 不能替代 PostgreSQL/备份/服务端故障告警 |

## 4. 本轮范围

| 模块 | 优先级 | 本轮交付 | 可接受降级 | 明确延期 |
| --- | --- | --- | --- | --- |
| 邮箱 OTP 登录 | P0 | 请求、校验、Session、退出、限流提示、国内主流邮箱送达验证 | Better Auth + 腾讯云 SES API | 密码、手机号、社交登录、学校 SSO |
| 邀请码/学校白名单 | P0 | 学校归属、启停、有效期、使用上限 | 管理员通过简单页面或受保护脚本维护 | 自动对接学校学籍 |
| 数据持久化 | P0 | 保存核心输入、画像、题目、答案、报告和状态 | JSONB 保存复杂既有结构 | 用户侧完整历史产品、数据仓库 |
| 隐私授权 | P0 | 协议版本、同意时间、撤回/删除请求留痕 | 删除由管理员人工执行 | 自动化 DSAR 工作流、正式法律审计 |
| 报告反馈 | P0 | 1–5 星、可选短文本、关联训练记录 | 不阻断报告 | 复杂问卷和访谈系统 |
| 产品事件与看板 | P0 | 注册、开始、完成、失败、反馈、核心延迟和用量 | 简单 admin 页面 + SQL/托管平台 | BI 平台、数据仓库、实时大屏 |
| 异常监控 | P0 | 前后端异常、关键 API 错误和告警 | 托管错误监控 + 结构化日志 | 完整 APM/SOC/NOC |

| 灰度发布 | P0 | 10–20 → 50 → 100 人分批门禁 | 手工放量和检查 | 自动化实验平台 |

| 用户历史列表 | P1 | 数据已保存但不做正式产品页 | 管理员可查询 | 搜索、筛选、对比趋势 |

## 5. 成功标准

| 指标 | 受控内测门槛 | 说明 |
| --- | ---: | --- |
| OTP 请求成功率 | ≥ 95% | SES 接受发送；排除明显非法邮箱和被限流请求 |
| OTP 验证成功率 | ≥ 85% | 以已成功发送验证码的邮箱为分母 |
| 国内邮箱样本送达 | QQ、163、两所学校域名各 ≥ 3/3 | G0/G1 使用真实收件箱记录时延与垃圾箱情况 |
| 主闭环完成率 | ≥ 60% | `session_completed / session_started`，服务端事件口径 |
| 模型调用失败率 | < 2% | profile/questions/report 的最终失败；成功兜底单独统计 |
| 严重错误 | 0 个未处理 | 白屏、数据串用户、无法登录、无法生成报告属于严重错误 |
| 用户数据隔离 | 100% | 普通用户不能访问其他用户记录 |
| 反馈采集率 | ≥ 30% | 不作为上线阻断，仅用于内测质量评估 |
| 核心数据完整率 | ≥ 98% | 完成会话必须有用户、学校、输入、题目、答案和报告关联 |

阈值可在首批 10–20 人后校准，但变更必须记录原因和基线数据。

## 6. 非目标

- 不承诺公开注册、正式 SLA、自动扩容或多区域容灾。
- 不保存原始音频，不做音频上传历史。
- 不把 Demo fallback 结果伪装成真实模型结果。
- 不允许普通用户访问 Prompt、全局声线、管理看板或删除执行接口。
- 不在本轮建设用户画像 B 端开放、猎头 SaaS、支付或多人协作。

## 8. 技术栈适配核对记录

| 维度 | 结论 | 执行门禁 |
| --- | --- | --- |
| 国内邮箱 | 不假设海外 Auth 默认邮件通道适配 QQ/163/学校邮箱 | 腾讯云 SES 域名、模板审核完成；4 类邮箱各做真实收件测试 |
| 认证 | Better Auth Email OTP 支持数字验证码、有效期、尝试次数和 Cookie Session | 锁版本；认证表通过生成 SQL 纳入版本控制 |
| 数据库 | 应用和腾讯云 PostgreSQL 置于同地域/VPC；开发使用本地 PostgreSQL | 空库 migration、备份/恢复、双用户隔离通过 |
| 邮件调用 | 使用腾讯云 SES API，不以 SMTP 为默认实现 | Secret 仅服务端；记录 provider requestId，不记录 OTP |
| 退出策略 | Auth、邮件和业务仓储均经项目内 adapter 封装 | 更换邮件商不改变公开 Auth API；数据库可标准 SQL 导出 |
